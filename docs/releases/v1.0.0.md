# OpenBEXI Timeline 1.0.0

Version 1.0.0 publishes the current OpenBEXI Timeline 2.0 source in
[`arcazj/openbexi_timeline2.0`](https://github.com/arcazj/openbexi_timeline2.0),
using the `master` branch and release tag `v1.0.0`.

## Included

- JavaScript and Three.js timeline with synchronized overview, events, duration sessions, colored zones, measured labels, and vertical row pagination.
- Adaptive and uniform time scales, manual magnification, momentum navigation, calendar controls, search, descriptors, and Timeline/Table/Split views.
- Standalone HTML build with complete local snapshots, JSON import/export, offline help, PNG export, and six bundled datasets containing 2,349 records.
- Read-only legacy JSON archive browsing with multiple source paths, namespace grouping, favorites, dated partitions, on-demand loading, and safe descriptor sidecars.
- Separate Python JSON-file workspace APIs for records, configuration, scoped identities, audit, and backup/restore primitives, with a single writer per storage root.
- Shared Local/Server provider contracts, versioned visual models, schemas, filters, views, and settings; an opt-in version-2 sorting/filtering workflow with safe regex, typed conditions, relationship context, natural ordering, group collapse, and reviewed migration.

## Download and Run

The [GitHub release](https://github.com/arcazj/openbexi_timeline2.0/releases/tag/v1.0.0)
provides the source archives for `v1.0.0`. This release does not include a newly
built standalone ZIP or a Python runtime. Follow the
[quick-start instructions](https://github.com/arcazj/openbexi_timeline2.0/blob/v1.0.0/README.md#quick-start) to install dependencies
and build `dist/index.html`, or run the Python service from source.

Deployment of the demo at the new repository's GitHub Pages address has not
been verified for this release.

## Known Limitations

- Full legacy compatibility, accessibility, cross-browser/platform behavior, performance budgets, and production hardening remain incompletely qualified.
- Local imports are limited to 25,000 records / 64 MiB. Oversized inputs are rejected rather than truncated.
- Local edits remain in memory until explicit JSON export; they do not synchronize automatically or constitute a server backup.
- Writable server storage supports one writer process per JSON root on local disk. Multiple workers and shared network storage are unsupported.
- Broader visual-model/camera compatibility, migration coverage, large-dataset preparation performance, and several administration and editing workflows remain open; consult implementation status for the detailed scope.
- Some historical dates and artwork remain uncertain or unavailable. Prior screenshots do not establish pixel-equivalent legacy rendering or fresh release validation.
- Dataset/image publication approval does not replace third-party permissions or cover arbitrary future imports.
