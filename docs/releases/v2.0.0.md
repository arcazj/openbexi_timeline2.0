# OpenBEXI Timeline 2.0

Version 2.0 simplifies the timeline around the legacy interface and a YAML entry
point selecting its model, filter and data sources.

- Compact toolbar with Timeline, Table and Split views, calendar navigation,
  overview visibility, 2D/3D controls, settings and Help.
- Data-driven grouping choices, including status and namespace when present,
  with deterministic sorting and parent/session relationships.
- Coordinated `yaml/`, `models/`, `filters/` and `data/` environments, filter-owned
  initial ranges, and generator support for complete new environments.
- Legacy REST compatibility, bounded past/future loading, and bundled Swagger UI.
- Automatic dependency setup through `python scripts/start.py`, including
  IntelliJ launch configurations and Python 3.9–3.14 dependency selections.
- Six [live datasets](https://arcazj.github.io/openbexi_timeline2.0/), with direct
  dataset links in the README. The default operations demo has 1,008 records from
  August 13 to October 12, 2026; its original 48 records remain unchanged.
- Seven primary Markdown guides, including a user manual. Redundant PDFs,
  PDF-only tooling and failed screenshot captures were removed from the checkout.

Start a checkout with `python scripts/start.py`. The launcher installs the locked
dependencies and builds the client; its first run needs package-registry access.
Existing workspaces keep their stored data. The expanded sample applies to new
workspaces and to explicitly opening the bundled default dataset.

Validation results and remaining platform limits are recorded in
[the test guide](https://github.com/arcazj/openbexi_timeline2.0/blob/v2.0.0/docs/openbexi_timeline2.0_tests.md).
Future Python versions are not guaranteed until their dependencies and tests
have been qualified. Historical datasets retain their original date uncertainties
and attribution notices.
